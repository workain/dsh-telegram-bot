# Приёмка предварительной версии

Это план отдельного прогона, **не свидетельство выполненной приёмки**. Автотесты синтетические; реальная доставка и UI ещё валидируются. Preview развивается и не принят в эксплуатацию или на всех устройствах.

## Подготовка

- Установить проверенную версию в существующий Web-профиль DSH, загрузить браузерный клиент Workain обновлением страницы. Не запускать второй Host для тех же журналов.
- Выделенный бот: Topics/threaded mode, один poller, без чужого webhook. Токен — только через credentials UI, не в чат, GitHub или отчёт.
- Привлечь **двух реальных доверенных операторов** с разными Telegram ID и личными чатами. Проверить числовой ID и логин с необязательным `@` без учёта регистра. Числовой ID рекомендован; все допущенные операторы доверены на уровне машины, проектных ACL нет.
- Выбрать тестовые проекты без секретов и персональных данных; `/watch all` разрешает передачу выбранных текстов в Telegram.
- Для телефона владелец задаёт достижимый Web DSH address через свой VPN/reverse proxy. Пустая настройка использует Host origin, часто localhost. Не открывать порты автоматически.

## Сессии и два личных чата

1. Оба оператора выполняют `/sessions`; проверить три массовые кнопки глобально и в проекте: работающие (`running=true`, не просто загруженные), последний час и сутки по штатному `updatedAt`.
2. Проверить `/connect running|hour|day [workspace]`, включая границы времени и проекта. Выбор через `s/c/f` сразу создаёт/открывает тему точного исходного session ID; `/fork` недоступен, копии сессии нет.
3. В обоих чатах связать одну исходную сессию: темы и привязки независимы. `/bind` занятой темы к другой сессии отклоняется; исходная идентичность не меняется.
4. Оператор A выбирает `/watch` одного проекта, B — другого. Изменения, `all`, пауза и возобновление A не сбрасывают выбор/привязки B. Новые проекты не добавляются в ранее выбранный `all` автоматически.
5. Начать обычную сессию из Web в выбранном проекте: появляется тема соответствующего чата. Невыбранный проект не пересылается; архивы и подагенты не обнаруживаются автоматически.
6. `/new` создаёт отдельную сессию со штатными моделью/preset/разрешениями. Подключение существующей сессии не меняет их.

## Текст, история и очередь

7. Написать настоящий человеческий текст в Web и получить зафиксированный ответ assistant. Оба текста видны в Telegram; reasoning, сырые tool args/results отсутствуют. Проверить обычный и многочастный длинный текст: одно исходное сообщение — одно Telegram-сообщение, кроме необходимого разбиения по лимиту.
8. При подключении проверить последний час: только человеческий `sourceKind=user` и текст assistant. Кнопка старых сообщений и `/history older` дают не более 200 исходных сообщений за порцию; следующая порция только по явному запросу, не вся история сразу.
9. Во время загрузки истории запустить новые ходы. Фиксированный начальный срез, учёт отправленной истории и граница живых событий не дают обычных повторов/наложений. Повторить после следующего хода и перезапуска runtime. Сетевой exactly-once не заявляется.
10. На тестовом состоянии старого формата проверить одноразовое отдельное переиздание текущего последнего часа; старые объединённые сообщения остаются. Следующий запуск не повторяет миграцию.
11. Отправить из Telegram два сообщения во время хода: штатная очередь той же исходной сессии, без прерывания, fork и переопределения модели/разрешений. Проверить их в Web.
12. `/stop` останавливает текущего агента и очищает очередь; отдельные jobs/подагенты не объявляются остановленными. При `/watch off` → ход из Web → `/watch on` период паузы автоматически не догружается.

## Вопросы и разрешения: оба направления и UI

13. Для вопроса с вариантами, свободного ответа и tool approval убедиться, что **Web и Telegram показывают один запрос одновременно**. Ответить в Telegram: Web закрывает проигравшую ветку, native запрос получает ровно первый действительный ответ.
14. Повторить те же три случая с ответом **из Web**: Telegram закрывает запрос/кнопки, поздний callback не отвечает на новый вопрос. Проверить близкие одновременные ответы: выигрывает только первый действительный.
15. При активном вопросе/approval отключить Telegram, выполнить `/watch off`, затем отдельно dispose/restart. Закрывается только Telegram-ветка, **Web остаётся работоспособен**, исходный native signal зеркалом не отменяется.
16. Проверить отменённые и устаревшие callbacks, отзыв допуска и политику `never`: запрет не превращается в Allow и ни одним каналом не обходится.

## Закреплённая ссылка и браузер

17. В новой теме ссылка содержит точный `?dshSession=<id>`, отправляется и закрепляется. После обычной аутентификации браузерный Workain открывает именно эту сессию через native `ctx.uiWorkspace.openSession`, не другую/новую.
18. Проверить два устройства и обновление Web: без загруженного Workain сам DSH 0.2.1 URL не маршрутизирует; после загрузки переход работает. Ссылка не заменяет браузерную авторизацию.
19. Проверить пустой Web DSH address, доступный владельцу VPN/reverse proxy base и недостижимый с телефона localhost. База с auth token, query или userinfo отклоняется, секрет не попадает в закрепление. Порты не открываются.
20. После успешной отправки ID сохраняется до pin. При недостатке прав повторяется закрепление того же ID без новой ссылки. Неизвестный исход отправки ссылки блокирует автоматический повтор и требует ручной сверки.

## Доступ, сбои и откат

21. Пустой allowlist запрещает доступ. Закрепить логин первым аутентифицированным update; другой Telegram ID с тем же логином отвергается. Отзыв A запрещает его новые отправки/callbacks, но не ломает независимый чат B.
22. При определённом отказе создания темы Bot API 4xx ожидание снимается; при timeout/неизвестном исходе блокировка сохраняется. Осмотреть темы: существующую использовать/привязать, не переносить идентичность. Только после проверки отсутствия `/retry <session-id>` предлагает явную кнопку подтверждения повтора.
23. Неизвестная отправка ссылки остаётся отдельной блокировкой до ручной сверки; `/retry` темы не стирает её автоматически. Не повторять вслепую и не удалять состояние ради обхода.
24. Перезапуск Telegram runtime и безопасный перезапуск того же DSH не дублируют темы/обычную историю. Повреждённые привязки блокируют запуск. Сбой Telegram не отменяет работающий агент.
25. Для отката отключить bundle в существующем профиле; при необходимости безопасно перезапустить тот же DSH. Не удалять сессии, журналы, темы или credential автоматически.
26. Приватное состояние `telegram-workain` в DSH home — незашифрованный текст с фрагментами, последовательностями истории, pin/message ID и привязками. Проверить ограничение доступа ОС; снимки не публиковать. Никаких заявлений о юридическом соответствии.

В отчёте записать версию плагина и DSH, результаты каждого пункта, два реальных оператора без публикации их ID, устройства/браузеры, оба направления ответов и ограничения. Не включать токены, приватные пути или текст чатов. Для GitHub — только поддерево плагина с MIT и upstream credit, без состояния машины. Непройденные реальные проверки оставить явно непринятыми.
