# Приёмка предварительной версии

Этот список выполняется **после** локальных тестов и установки проверенного commit в существующий Web-профиль DSH. До отдельного прогона реального Telegram версия не считается принятой в эксплуатацию.

## До подключения

- Использовать выделенного бота, не занятого другим poller/webhook.
- Сохранить токен через credentials UI DSH, не в чат, GitHub или YAML.
- Ровно один числовой ID владельца; только личный чат.
- Выбрать тестовый проект без секретов и персональных данных. `/watch all` означает передачу новых итогов всех выбранных проектов Telegram.
- Не открывать HTTP-порт DSH в интернет и не запускать второй Host для тех же сессий.

## Проверки на телефоне и в Web

1. `/sessions` → выбрать существующую сессию. История автоматически не выгружается; последующие события идут в её тему.
2. Начать ход в Web. В Telegram видны краткий прогресс и итог того же хода, без reasoning и аргументов инструментов.
3. Отправить два сообщения в тему во время работы. Они входят в общую очередь той же сессии, не прерывают текущий ход и не создают новую сессию.
4. `/watch <workspace-id>` → начать другую сессию в выбранном проекте из Web. Для неё появляется отдельная тема. Невыбранный проект не пересылается.
5. `/new` в проекте → отдельная новая сессия. Проверить в Web модель, preset и разрешения: они наследуются штатно, не заменяются при открытии темы.
6. В уже связанной сессии запросить вопрос с вариантами, свободный ответ и tool approval. Ответить с телефона; отменить запрос и убедиться, что старые кнопки не отвечают на следующий вопрос. Политика `never` не должна показывать обходящий её Allow.
7. `/stop` во время работы и с очередью. Текущий агент получает отмену, ожидающая очередь очищена. Отдельные фоновые задания/подагенты не объявляются остановленными.
8. `/watch off` → запустить ход в Web → `/watch on`. Содержимое периода паузы не догружается после включения. Захваченные Telegram вопросы при паузе закрываются; при необходимости повторить их в Web.
9. Перезапустить только Telegram runtime. Уже существующие темы не дублируются, прошлые события не рассылаются заново. Повторить для перезапуска существующего DSH только после безопасного завершения работы.
10. Удалить владельца из allowlist. Новые отправки и старые callbacks недоступны. Вернуть доступ явно и перепроверить на тестовой сессии.
11. Попробовать `/bind` занятой темы к другой сессии: перенос должен быть отвергнут, исходная сессия и её approvals не меняются. При восстановлении действительно потерянной связи использовать свободную тему.
12. Передать тестовый документ и изображение. Проверить в Web, что документ входит через receipt своей сессии, изображение читается как native image; бинарные данные или bot token не попадают в текст сообщений/логи.

## Сбои и откат

- Если исход отправки/создания неизвестен, сначала сверить `/sessions`, `/status`, темы и очередь в Web. Не повторять вслепую и не удалять состояние, чтобы «починить» ошибку.
- Повреждённые связи должны блокировать запуск, а не создавать новые темы автоматически. Восстанавливать только проверенный локальный снимок состояния при остановленном Telegram runtime.
- Для отката отключить bundle этого плагина в существующем профиле; при необходимости безопасно перезапустить этот же DSH. Не удалять сессии, журналы, темы или credential автоматически.
- Состояние плагина хранится в каталоге `telegram-workain` внутри DSH home. Снимок содержит чувствительные привязки/черновики: хранить локально с ограниченным доступом, не прикладывать к публичному issue.

В отчёте приёмки записать commit плагина, версию DSH, результаты пунктов, проверенные устройства и оставшиеся ограничения — без токенов и содержимого пользовательских чатов.
